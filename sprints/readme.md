
> feature‑user‑login
>
> 🔹**业务目的**：让已有注册用户可以验证身份进入系统；区分登录/未登录状态，保护需要鉴权的功能（例如前面的头像上传）。
> 🔹**技术目的**：建立统一身份认证、会话管理、错误提示规范；沉淀登录相关安全方案（防暴力破解、密码传输、token 管理），后续所有需要登录的功能复用这套鉴权。
> 🔹**本次**不做：注册、忘记密码、短信登录、第三方登录（明确排除，防止范围蔓延）。

## 01_需求文档_PRD / user_login_prd_official.md
**功能概述**
已注册用户输入账号+密码，校验通过后获得登录态；登录态保持一段时间；支持退出登录；账号密码错误给出提示；未登录访问受保护页面自动跳转到登录页。

**业务规则**
1. 账号：手机号 / 用户名（按你们系统已有的注册字段）
2. 密码：6‑32位
3. 会话有效期：7天免登录；关闭浏览器默认不清除（可加“记住我”复选框）
4. 同一账号多处登录允许共存（可选：也可设计成“新登录踢掉旧会话”，业务自行决定）
5. 连续5次密码错误：**锁定15分钟**，期间禁止尝试（防暴力破解）
6. 登录成功跳转：回到登录前原本想去的页面；无来源则跳转到首页。

**权限规则**
- 未登录：仅可访问公开页面；访问受鉴权页面自动重定向至登录页。
- 已登录：可以访问自己有权限的功能。
- 已登录用户手动点“退出登录”，销毁服务端会话/前端token，回到未登录状态。

**交互流程**
1. 用户进入登录页
2. 输入账号、密码；可选勾选「记住我」
3. 点击登录 → 出现 loading
4. 成功：保存登录凭证，跳转目标页面
5. 失败：在页面展示对应错误文案（账号不存在 / 密码错误 / 已锁定），**不清空账号输入框，仅清空密码**
6. 导航栏出现「退出登录」按钮；点击确认后注销登录态。

**不做（Out‑of‑Scope）**
- 注册、找回密码、验证码登录、微信/QQ登录、生物识别登录，不在本次迭代。

## 02_验收标准_AC / user_login_ac_standard.md
- AC1：正确账号密码可以登录，刷新页面登录态保留（勾选记住我）。
- AC2：密码错误返回友好提示；不会提示“账号是否存在”（安全原则：不泄露账号是否注册）。
- AC3：连续5次错误登录后账号锁定15分钟，期间登录被拒绝并有提示。
- AC4：点退出登录，登录态清除；再访问需要登录的页面会被重定向回登录页。
- AC5：未登录直接在地址栏输入受保护页面URL，自动跳转到登录页；登录成功后回到刚才想去的页面。
- AC6：网络异常、接口500时页面给出“网络异常，请稍后重试”，不会卡死。

> draft_ai 版本可以让AI先生成一份初稿，再人工删减、修正安全规则，另存为 official。

## 03_测试用例_检测清单 / user_login_test_checklist.md
**功能**
- ✅ 正确账号密码登录成功，登录态保存
- ✅ 退出登录成功，鉴权失效
- ✅ “记住我”勾选与否登录态有效期行为符合预期

**边界 & 异常输入**
- ✅ 账号为空 / 密码为空 → 前端提示必填
- ✅ 账号、密码超长字符输入（35位以上）被拦截或服务端拒绝
- ✅ 密码连续5次错误触发锁定；15分钟后恢复

**安全**
- ✅ 多次错误登录**不能告知“账号不存在”**，统一“账号或密码不正确”
- ✅ 密码在网络传输必须走 HTTPS，禁止明文
- ✅ 前端localStorage/cookie存储凭证符合安全属性（HttpOnly优先）
- ✅ 退出后旧的token/session失效，不能继续调用鉴权接口

**兼容**
- ✅ PC、移动端登录表单正常显示；按钮、输入框可以正常点击。

## 04_后端开发
**接口文档要点**
- `POST /api/auth/login`
  请求：`{account: string, password: string, remember: boolean}`
  返回：`{code, msg, data:{token/会话id, user_info}}`
- `POST /api/auth/logout`（需鉴权）销毁会话
- 鉴权中间件：统一拦截未授权请求，返回401；可配置全局重定向地址给前端。

**数据库变更**
- user 表不需要新增字段；需要一张 `user_login_session` 表记录活跃会话、过期时间、设备信息（可选）；
- login_failed_record 记录表用于计数密码错误，实现登录锁定。

**开发技术方案重点**
- 密码**禁止明文存储**，使用 bcrypt / argon2 哈希；数据库里永远不要存原始密码。
- 暴力破解计数按账号统计；锁定时间存在缓存或数据表。
- Token / Session 方案二选一：
  - Session：存在Redis；适合中小型项目，便于后端主动踢人。
  - JWT：无状态；但后端很难单方面注销，需要额外维护黑名单，适合分布式场景。
> 建议中小系统优先选 Redis Session，运维简单，可控性更好。

## 05_前端开发
- 登录页面表单组件：账号、密码输入框、记住我复选框、登录按钮、loading状态。
- 全局鉴权拦截器：axios/fetch请求响应拦截，收到401自动跳转登录页，**保存来源URL方便登录后返回**。
- 导航栏“退出登录”按钮组件；点击弹出确认提示，调用logout接口，清除本地凭证。
- 路由守卫：路由跳转前检查登录状态，未登录自动重定向登录页。

**开发价值**：沉淀一套统一鉴权拦截、全局401处理方案，后续头像上传等所有受保护页面直接复用，不用每个页面重复写判断。

## 06_运维部署
- Nginx 强制全站 HTTPS；HTTP访问301重定向HTTPS。
- Redis 部署/配置（Session方案需要）；做好过期策略。
- 新增登录、登出接口日志埋点：记录账号、时间、IP、是否成功登录（脱敏，不要记录密码），用于安全审计。
- 上线检查项：HTTPS证书有效；Cookie设置 Secure、SameSite 属性；生产环境关闭调试错误详情。
