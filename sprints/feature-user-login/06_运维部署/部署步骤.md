# 部署步骤 — 用户登录

> 迭代：feature-user-login

---

## 一、前置准备
- [ ] 确认目标环境（QA / UAT / PROD）
- [ ] 确认 HTTPS 证书已就绪且未过期
- [ ] 确认 Redis 实例可用（Session 方案必需）
- [ ] 确认数据库 backup 已完成

---

## 二、后端部署

1. **执行数据库变更**
   ```bash
   mysql -h <host> -u <user> -p <db> < 04_后端开发/数据库变更SQL.md 中的 SQL
   ```
   > 建议先在 QA 库执行验证，生产走 DBA 审核流程。

2. **配置环境变量**
   - `AUTH_SESSION_TTL=604800`（7 天，单位秒）
   - `AUTH_SESSION_SHORT_TTL=7200`（未勾选记住我 2 小时）
   - `AUTH_LOCK_THRESHOLD=5`
   - `AUTH_LOCK_DURATION=900`（15 分钟）
   - `REDIS_URL=redis://xxx`
   - `BCRYPT_COST=10`

3. **发布后端服务**（按团队 CI/CD 流程），滚动发布避免会话中断。

4. **验证接口**
   ```bash
   curl -X POST https://<host>/api/auth/login \
     -H "Content-Type: application/json" \
     -d '{"account":"test","password":"xxx","remember":true}'
   ```

---

## 三、前端部署

1. 拉取本迭代分支，执行构建：
   ```bash
   npm ci
   npm run build:qa   # 或 build:uat / build:prod
   ```
2. 将 `dist/` 产物上传到静态服务器 / CDN。
3. 校验入口 HTML 引用的 hash 资源已发布。

---

## 四、Nginx / 网关配置

见 `06_运维部署/nginx配置变更.md`。发布顺序：**先后端，后 Nginx，最后前端**（避免用户拿到新前端却打旧接口）。

---

## 五、灰度 & 回滚

- **灰度**：先 5% 流量 → 观察登录失败率、5xx、锁定率 30 分钟 → 全量
- **回滚触发指标**：
  - 登录成功率下降 > 5%
  - 5xx 明显上升
  - Redis 连接异常
- **回滚步骤**：
  1. 前端切回上一版本（CDN 回滚）
  2. 后端切回上一版本（滚动回退）
  3. 数据库表**保留**（新表不影响旧代码）
  4. 事后复盘

---
