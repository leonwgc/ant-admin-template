# 前端页面交互逻辑 — 用户登录

> 迭代：feature-user-login

---

## 一、登录页交互时序

```
用户进入 /login
  │
  ├─ URL 携带 ?redirect=xxx → 记录到本地变量
  │
  ▼
输入账号 / 密码 / 记住我
  │
  ▼
点击「登录」
  │
  ├─ 前端表单校验（空值 / 长度）
  │    └─ 不通过 → 输入框下方红字提示，终止
  │
  ├─ 按钮 disable + loading
  │
  ▼
POST /api/auth/login
  │
  ├─ 200 success
  │    ├─ store.setUser(data.user_info)
  │    ├─ 若 JWT 方案：store.setToken(data.token)
  │    ├─ message.success('登录成功')
  │    └─ navigate(redirect || defaultRoute, { replace: true })
  │
  ├─ 40001 账号或密码错误
  │    ├─ Alert / 顶部提示「账号或密码不正确」
  │    ├─ 密码框清空，账号保留
  │    └─ 按钮恢复
  │
  ├─ 40002 已锁定
  │    ├─ Alert「账号已被锁定，请 15 分钟后重试」
  │    └─ 按钮恢复
  │
  └─ 网络/500
       ├─ message.error('网络异常，请稍后重试')
       └─ 按钮恢复
```

---

## 二、未登录访问受保护页

```
用户访问 /app/xxx
  │
  ▼
RouteGuard 检查 store.user
  │
  ├─ 已登录 → 继续 operations 权限判断
  │
  └─ 未登录
       └─ Navigate to `/login?redirect=/app/xxx` replace
```

登录成功后：
```
navigate(decodeURIComponent(redirect), { replace: true })
```

---

## 三、退出登录

```
Header 用户头像 → 下拉菜单 → 退出登录
  │
  ▼
Modal.confirm 二次确认
  │
  ├─ 取消 → 关闭
  │
  └─ 确认
       ├─ POST /api/auth/logout
       ├─ store.clearUser()
       ├─ localStorage 清除 user
       ├─ message.success('已退出登录')
       └─ navigate('/login', { replace: true })
```

---

## 四、页面刷新恢复登录态

```
App 挂载
  │
  ▼
读取 localStorage 中的 user（若持久化）
  │
  ├─ 存在 → store.setUser(cached) → 后台异步调用 /api/auth/me 校验
  │            ├─ 成功 → 用最新数据覆盖
  │            └─ 401 → clearUser + 跳登录
  │
  └─ 不存在 → 保持未登录
```

---

## 五、全局 401 拦截

由 `src/req.ts` 响应拦截统一处理：
- 收到 401 → 清 store → 跳登录页并带 redirect
- **注意**：`/api/auth/login`、`/api/auth/me` 自身的 401 不做全局跳转（否则会死循环）

---

## 六、边界与状态

| 场景 | 期望行为 |
| --- | --- |
| 已登录访问 `/login` | 自动跳 `defaultRoute` |
| 登录接口 pending 期间用户切页面 | 卸载时取消请求，不更新已卸载组件 |
| 输入过程中失焦 | 校验规则仅在提交时触发，避免过度打扰 |
| 移动端软键盘弹出 | 输入框不被遮挡（可在 SCSS 内做 padding 处理） |
