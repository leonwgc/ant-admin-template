# 后端技术方案 — 用户登录

> 迭代：feature-user-login

---

## 一、总体架构

```
Client ──HTTPS──> Nginx ──> Auth API
                              │
                              ├── User Service (账号校验)
                              ├── Password Hash (bcrypt/argon2)
                              ├── Session Store (Redis) 或 JWT
                              └── Rate Limit / Lock (Redis)
```

---

## 二、密码存储

- **禁止明文**存储密码
- 使用 `bcrypt`（cost ≥ 10）或 `argon2id`
- 每个用户独立 salt（bcrypt 自带）
- 校验：`bcrypt.compare(input, hashInDB)`
- 数据库中**永远**不出现原始密码

---

## 三、会话方案（二选一）

### 方案 A：Redis Session（推荐中小系统）
- 登录成功后生成随机 `sessionId`（>=32 字节），存 Redis
- Key: `sess:{sessionId}` → Value: `{user_id, roles, expires_at}`
- TTL：`remember=true` 7 天；否则 2 小时
- 前端凭证：Cookie（`HttpOnly` + `Secure` + `SameSite=Lax`）
- **优点**：可主动踢人、可查活跃会话、无黑名单负担

### 方案 B：JWT（适合分布式 / 多服务）
- payload 只包含 `user_id`, `exp`, `iat`, `jti`
- 密钥严格管理（RSA 私钥 / HS256 密钥 → KMS 或环境变量）
- 主动注销需维护 `jwt_blacklist`（Redis，TTL = 剩余有效期）
- **缺点**：无状态导致踢人复杂

> 本迭代**建议方案 A**，运维简单，可控性好。

---

## 四、防暴力破解

- Key: `login_fail:{account}` → 计数
- 每次密码错误 `INCR`，设置滑动 15 分钟 TTL
- 计数 >= 5 → 写入 `login_locked:{account}`，TTL 15 分钟
- 锁定期间任何登录尝试直接返回 `40002`
- 登录成功后清空计数

**可选加强**：
- IP 维度也做限流（防止撞库）：`login_fail_ip:{ip}` 100 次/小时
- 触发锁定后要求下次登录带图形验证码

---

## 五、登录接口时序

```
1. 参数校验（账号格式、密码长度）
2. 检查 login_locked:{account} → 若锁定，直接返回 40002
3. 查 user by account
   - 用户不存在 → 记 fail_count（防止用户名枚举）→ 返回 40001
4. bcrypt.compare(password, user.password_hash)
   - 失败 → INCR fail_count → 达到阈值则加锁 → 返回 40001
5. 成功：
   - 清 fail_count
   - 生成 sessionId（或 JWT）
   - 写入 user_login_session
   - Set-Cookie（HttpOnly / Secure / SameSite）
   - 返回 user_info
```

## 六、安全清单
- [x] HTTPS 强制
- [x] 密码哈希存储
- [x] 错误提示统一，不泄露账号是否存在
- [x] 暴力破解锁定
- [x] Cookie 三属性（HttpOnly / Secure / SameSite）
- [x] 敏感字段不落日志
- [x] SQL 参数化查询，防注入
- [x] 登出后凭证立即失效

---

## 七、埋点 / 审计日志

登录、登出、登录失败均需埋点：
```
{event, account_masked, ip, ua, timestamp, success, reason}
```
`account_masked` 例：`138****5678`；**禁止**记录密码。
